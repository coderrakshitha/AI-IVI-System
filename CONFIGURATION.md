\# AI-IVI-System Configuration Guide



This document contains the configuration required to run the AI-IVI-System on another computer.



\## 1. React Configuration



The React application runs using Vite.



Default development URL:



&#x20;   http://localhost:5173



Start the React application from the project root:



&#x20;   npm install

&#x20;   npm run dev



\---



\## 2. Node.js Configuration



The Node.js backend is located inside:



&#x20;   server/



Install the backend dependencies:



&#x20;   cd server

&#x20;   npm install



Start the Node.js server:



&#x20;   npm start



The server runs on:



&#x20;   http://localhost:3000



\---



\## 3. n8n Configuration



The project uses n8n for workflow automation.



The n8n workflow is provided in:



&#x20;   n8n/IVI-System.json



Import this file into n8n.



The local n8n instance used by the project runs on:



&#x20;   http://localhost:5679



\---



\## 4. Telegram Configuration



The project uses a Telegram Bot as the external input interface.



Create a Telegram Bot using BotFather.



After creating the bot:



1\. Copy the Telegram Bot Token.

2\. Open n8n.

3\. Create a Telegram API credential.

4\. Enter the Bot Token.

5\. Assign the credential to the Telegram Trigger node.



Do not commit the Bot Token to GitHub.



Each user should create and use their own Telegram Bot.



\---



\## 5. OpenRouter Configuration



The AI Agent uses an OpenRouter Chat Model.



To configure OpenRouter:



1\. Create an OpenRouter account.

2\. Generate an API key.

3\. Open n8n.

4\. Create an OpenRouter API credential.

5\. Enter the API key.

6\. Assign the credential to the OpenRouter Chat Model node.



Do not commit the OpenRouter API key to GitHub.



Each user should use their own API key.



\---



\## 6. Cloudflare Tunnel Configuration



Telegram requires a publicly accessible HTTPS webhook.



Because n8n is running locally, a Cloudflare Tunnel is used.



Start the tunnel with:



&#x20;   cloudflared tunnel --url http://localhost:5679



Cloudflare generates a temporary HTTPS URL.



Example:



&#x20;   https://example-name.trycloudflare.com



Use the generated HTTPS URL when configuring the n8n webhook.



The URL may change when the Cloudflare Quick Tunnel is restarted.



\---



\## 7. n8n to Node.js Configuration



The Node.js server runs on the host computer at:



&#x20;   http://localhost:3000



Since n8n runs inside Docker, the HTTP Request node should use:



&#x20;   http://host.docker.internal:3000/ivi-screen



Do not change this to localhost when n8n is running inside Docker.

\## 9. Startup Order



For a fresh setup, the recommended order is:



\### Step 1



Start Docker Desktop.



\### Step 2



Start the n8n container.



\### Step 3



Open n8n:



&#x20;   http://localhost:5679



\### Step 4



Import:



&#x20;   n8n/IVI-System.json



\### Step 5



Configure Telegram credentials.



\### Step 6



Configure OpenRouter credentials.



\### Step 7



Start the Node.js server:



&#x20;   cd server

&#x20;   npm install

&#x20;   npm start



\### Step 8



Start React in another terminal:



&#x20;   npm install

&#x20;   npm run dev



\### Step 9



Start Cloudflare Tunnel:



&#x20;   cloudflared tunnel --url http://localhost:5679



\### Step 10



Configure the generated HTTPS URL for the Telegram webhook.



\### Step 11



Activate the n8n workflow.



\### Step 12



Send a test command through Telegram.



Example:



&#x20;   Open music



The React application should open the Music screen.



\---



\## 10. Security



The following information must never be committed to the public GitHub repository:



\- Telegram Bot Token

\- OpenRouter API Key

\- Passwords

\- API secrets

\- Private credentials



Each user must configure their own credentials.



\---



\## 11. Important Note for New Users



The following values are specific to the original development computer and should not be copied blindly:



\- Cloudflare Tunnel URL

\- Telegram credentials

\- OpenRouter credentials



The new user should generate and configure their own values.



The application ports should remain:



&#x20;   React: 5173

&#x20;   Node.js: 3000

&#x20;   n8n: 5679



unless the user intentionally changes the configuration.
